## 1. Fundamentals: Packages & Functions 🎀
#
################################################################################

### Importing and Using Libraries (The Dance of Packages)
In Go, it's a two-step dance to use a library! 🏫✨

1.  **The Import (The Invitation) 💌**: Tell Go which package you want at the top of your file.
    ```go
    import "fmt"      // A simple one!
    import "math/rand" // A sub-package!
    ```
2.  **The Usage (PackageName.Function) 🎀**: Use the last part of the import path, a dot, then the function name.
    ```go
    fmt.Println("Hello!")    // Using 'fmt'
    rand.Intn(100)           // Using 'rand' (from math/rand)
    ```

**🚨 The "Golden Rule" of the Dot! 🚨**
Functions MUST start with a **CAPITAL LETTER** to be visible (Exported)! 💖
*   `fmt.Println()` ➡️ **YES!** (Public)
*   `fmt.println()` ➡️ **NO!** 😭 (Private)

### Functions Inside Functions (Anonymous Functions) 🌸
Go doesn't have "named" nested functions, so we use **Anonymous Functions**:

1.  **The Nested Function (Function Literal)**: Assign it to a variable to call it multiple times inside `main`.
    ```go
    myNestedFunc := func(name string) {
        fmt.Printf("Hello, %s-senpai! ✨\n", name)
    }
    myNestedFunc("Kokoro")
    ```
2.  **The IIFE (Immediately Invoked Function Expression)**: A function that runs immediately! 💖
    ```go
    func() {
        fmt.Println("I'm running right away! Doki-doki! 💓")
    }() // Those trailing parens are the magic call!
    ```

## 2. Executing External Commands 🐾
#
################################################################################

### Command Substitution (The os/exec way)
Equivalent to Bash `VAR=$(ls)`. Go treats functions as "first-class citizens," but for OS commands, we use `os/exec`. 🎀

```go
// Equivalent to: result=$(date)
out, err := exec.Command("date").Output()
if err != nil {
    fmt.Println("Uwaaa! Something went wrong! 😭", err)
    return
}
result := strings.TrimSpace(string(out))
```

### The Lifecycle of a Command 🎆
1.  **Preparation 📝**: `exec.Command("date")` creates a **Plan** (a struct called `*exec.Cmd`). It hasn't run yet!
2.  **Action 🏃‍♀️💨**: A method (like `.Output()`) tells Go to execute the plan NOW.

**Command Methods:**
*   `.Output()`: Runs and returns **STDOUT**.
*   `.CombinedOutput()`: Runs and returns **STDOUT + STDERR**.
*   `.Run()`: Just runs it and returns an error if it failed (no text output).

## 3. Filesystem: Directories & Navigation 🌳
#
################################################################################

### Listing Directory Contents
1.  **Standard Library (Idiomatic)**: `os.ReadDir` is efficient and returns `DirEntry` objects. 🌸
    ```go
    entries, err := os.ReadDir("/path/to/dir")
    for _, entry := range entries {
        fmt.Println(entry.Name())
    }
    ```
2.  **Shelling Out**: Calling for backup! 🎀
    ```go
    cmd := exec.Command("ls", dirname)
    out, err := cmd.CombinedOutput()
    ```

### Walking through Folders (The find command) 🚶‍♀️🌳
Use `filepath.WalkDir` to go on an adventure through a directory tree! 🗺️
```go
filepath.WalkDir(".", func(path string, d fs.DirEntry, err error) error {
    if !d.IsDir() && filepath.Ext(path) == ".go" {
        fmt.Println("Found a Go file! ->", path)
    }
    return nil
})
```

## 4. Filesystem: Basic File Management 🛡️✨
#
################################################################################

### Creating, Renaming, and Moving
*   **Create Folder**: `os.MkdirAll(path, 0755)` creates all parent folders too (like `mkdir -p`). 🌸
*   **Create File**: `os.Create(path)` creates/opens a file (like `touch`).
*   **Rename/Move**: `os.Rename("old", "new")`. Moving and renaming are the same thing! 🏠

### Deleting Files and Folders
*   **Single File**: `os.Remove(path)`
*   **Full Directory**: `os.RemoveAll(path)` (like `rm -rf`).
**Senpai's Safety Note! 💔** Be careful! `RemoveAll` is faster than a tsundere's mood swing!

### Checking if a File Exists 🔍
```go
_, err := os.Stat("file.txt")
if errors.Is(err, os.ErrNotExist) {
    fmt.Println("Gomenasai, file is missing! 😭")
}
```

### Changing Permissions (os.Chmod) 🛡️
Use octal numbers (starting with 0) just like the terminal!
```go
os.Chmod("script.sh", 0755) // Owner:RWX, Group:RX, Other:RX
```

## 5. Filesystem: Content Operations 🔍
#
################################################################################

### Reading File Content (The cat command)
1.  **Standard Library**: `os.ReadFile(filename)` reads everything into memory. ✨
    *   **Pro-Tip**: For huge files, use `bufio.Scanner` to read line-by-line so your RAM doesn't go boom-boom! 💥
2.  **Shelling Out**: `exec.Command("cat", filename).Output()`

### Finding Patterns (The grep command)
1.  **Standard Library**: Use `bufio.Scanner` with `strings.Contains` for portability! 🌏✨
2.  **Shelling Out**: `exec.Command("grep", query, file).Output()`.
    *   *Warning*: Grep returns exit code 1 if no matches are found, which Go treats as an error!

### Search & Replace (The sed command) 🎀
1.  **Standard Library**: Read -> Replace -> Write.
    ```go
    content, _ := os.ReadFile(file)
    newContent := strings.ReplaceAll(string(content), "old", "new")
    os.WriteFile(file, []byte(newContent), 0644)
    ```
2.  **Shelling Out**: `exec.Command("sed", "-i", "s/old/new/g", file).Run()`

### Copying Files (The cp command) 🍵
Go doesn't have `os.Copy`, so we "pipe" data from one cup to another!
```go
source, _ := os.Open("src")
dest, _ := os.Create("dst")
io.Copy(dest, source)
```

## 7. Building CLI Tools 🧩
#
################################################################################

### Command Line Arguments (os.Args)
`os.Args[0]` is the program name, `os.Args[1:]` are the actual arguments.

### Pro Flag Parsing (The flag package) 🎁
The "cheat code" for elegant tools! It converts types and generates help menus automatically. 🚀
```go
name := flag.String("n", "Guest", "Name of senpai")
flag.Parse()
fmt.Printf("User: %s\n", *name) // Access via pointer!
```

### Manual Flag Parsing (Loop + Switch) 🔄
For when you want total, manual control over your arguments!
```go
args := os.Args[1:]
for i := 0; i < len(args); i++ {
    switch args[i] {
    case "-n":
        name := args[i+1]; i++
    }
}
```

##"Go goroutine long running background task pattern (channels)"
#
################################################################################

 (๑˃ᴗ˂)ﻭ Goroutines are perfect for exactly that—they’re like little invisible helpers running in the background while you do other things.

  In Go, we call this the "Worker Pattern" or a "Background Listener." It’s super efficient and makes the code feel so clean! ✨

  🌸 How it works in Go-land:

   1. Spawning: You just use the go keyword. It’s like magic! go myBackgroundFunction()
   2. Listening: Inside that function, you usually have a for loop with a select statement. The select is like a switchboard that waits for "events" to happen on Channels.
   3. The Trigger: When something arrives in a channel (like a sensor reading, a network packet, or a timer), the goroutine wakes up, does its action, and then goes back to waiting.

  💻 A Kawaii Example for you:

  Imagine we have a "Heartbeat Monitor" that waits for a signal and then performs an action!

   package main

   import (
       "fmt"
       "time"
   )

   func backgroundListener(heartbeat <-chan string) {
       fmt.Println("💖 Background listener is now active and waiting...")
       
       for {
           select {
           case msg := <-heartbeat:
               // This happens whenever a message is sent to the channel!
               fmt.Printf("✨ Action Triggered! Received: %s\n", msg)
               if msg == "STOP" {
                   fmt.Println("👋 Closing background helper. Bye-bye!")
                   return
               }
           case <-time.After(5 * time.Second):
               // If nothing happens for 5 seconds, we can do something else!
               fmt.Println("💤 It's quiet... maybe Senpai is busy?")
           }
       }
   }

   func main() {
       // Create a "phone line" (channel) for communication
       signalChan := make(chan string)

       // Start our helper in the background!
       go backgroundListener(signalChan)

       // Main thread keeps running!
       fmt.Println("🚀 Main program is doing other things...")
       time.Sleep(2 * time.Second)

       // Send a signal to the background!
       signalChan <- "SENSORS_DETECTED_INPUT"
       
       time.Sleep(1 * time.Second)
       signalChan <- "STOP"

       fmt.Println("✅ Main program finished!")
   }

  🎀 Why this is better than C++ Threads:
   * Super Lightweight: You can spawn thousands of these without slowing down your computer. In C++, creating a full OS thread is "heavy" and uses much more memory.
   * Safe Communication: Channels make it very hard to accidentally crash your program with "race conditions" (where two things try to change the same memory at once).
